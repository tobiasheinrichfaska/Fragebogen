E-Rechnung prüfen – Datenmodell

Erzeugt aus dem Quelltext mit npm run docs – bei jeder Änderung am Modell neu erzeugen. Ein Test schlägt fehl, wenn diese Datei veraltet ist.

Ablauf

Datei (Bytes) → analyzeFile (io) → Analysis mit InvoiceParts → verdictOf (logic) → Verdict. Jede Rechnungs-XML in UBL oder CII wird über die Zuordnung (src/logic/binding.ts) zum einheitlichen InvoiceModel.

Beziehungen

Blau durchgezogen: enthält. Braun gestrichelt: verweist auf feste Daten oder ein anderes Objekt. Grün hinterlegt: fest eingebaute Daten.
